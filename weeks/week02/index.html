WEEK 02

開始用 Codex

Codex 已經裝好了，這週開始真的用它。先學怎麼交代：同一件事，說清楚四件事（目標、資料來源、界線、怎樣算做好），它就不用猜，你驗收也有標準。再學它動你的電腦之前會先問你：看懂它在問什麼再按，剛開始用 Ask for approval，密碼和別人的個資不要交給它。三支補充：用 VS Code 看、改 AI 寫的 .md 檔；AI 為什麼會很有把握地說錯；以及說不清楚的時候，用截圖、拖檔案、複製路徑交代給它。

影片 01同一件事，如何精準的交代給 AI Agent？

  1. 一句話，它只能用猜的。小安要準備考試，跟 Codex 說「幫我整理筆記」。「整理」是什麼意思，它不知道，只能自己猜：把檔案搬進 整理/、改了標題和格式，連期末報告草稿都一起改了。它讀的檔案裡還有期末報告草稿：我們甚至不能肯定，資料整理的來源是否正確。小安要的，其實是一份考前複習重點。

  2. 交代清楚四件事。目標（要做出什麼）、資料來源（用哪些資料、在哪裡）、界線（什麼不能碰）、怎樣算做好（你等一下怎麼驗收）。就像請朋友幫你買午餐：一個排骨便當、去校門口那家買、不要辣、12:10 前放我桌上。交代 Codex 也是同樣的四件事。

  3. 一段話，它照你的意思做。四件事一件一行：「幫我做一份考前複習重點，存成 複習重點.md。只用 week1.md 和 week2.md。不要改、不要搬原本的檔案。每週 5 點以內、每點一行，最後列出我可能還不懂的地方。」這次它不用猜：只多了一個檔案（複習重點.md +19），原本的都沒動。

  4. 怎樣算做好，由你決定。界線和怎樣算做好，就是你的驗收清單：看改了哪些檔案（原本的沒動）、數一數每週幾點、找到「我可能還不懂的」那一段。說清楚了，驗收就有標準。

  5. 自己跑一次。照 Week 1 影片 03，做你自己的自我介紹網頁：交代時把四件事都寫到，做完用你寫的「怎樣算做好」一條一條驗收；不對，就請它修。

影片 02它能動你的電腦，那誰說了算？核准與權限

  1. 電腦是一棟房子，專案資料夾是工作室。在工作室裡，Codex 自己讀檔、寫檔、跑指令；要改工作室外面的檔案、要出門連網路，它會先停下來問你。這就是 Ask for approval：工作室裡自己做，出去之前先問你。

  2. 它來問你，看懂再按。請 Codex 從網路下載一份資料，它要連網路，會先跳出核准，上面是它要執行的指令。按之前看兩件事：連去哪裡（網址）、存到哪裡（路徑）。看得懂、是你要的，再按 Approve request；看不懂，先按 Decline request，用中文問它：「這個指令在做什麼？」

  3. 三種權限模式。輸入框底下可以換：Ask for approval（改外面的檔案、連網路，都先問你）、Approve for me（它先自己判斷，可能不安全的才問你）、Full access（整台電腦、網路都能用，什麼都不問）。剛開始建議用 Ask for approval，每一步都看得到；Full access 等你熟了、專案有備份再考慮。

  4. 有些東西，不要交給它。密碼、API key（讓程式登入服務的鑰匙，和密碼一樣重要）、別人的個資（姓名、學號、電話），不要貼進對話，也不要放進專案資料夾：貼進對話的內容，會送到 AI 的伺服器。要用到別人的資料，名字換成代號、學號拿掉；怕它改壞，先備份一份資料夾。

補充 1VS Code 和 Markdown

  1. VS Code 是看檔案、改檔案的地方。不是寫程式才用。左邊 EXPLORER 是資料夾裡的檔案，點一下就打開；Codex 和 VS Code 看的是同一個資料夾，影片 01 Codex 寫的 複習重點.md 在這裡就看得到。

  2. 改完記得存檔。⌘S（Windows：Ctrl+S）。分頁上的 × 變成白點，就是還沒存；沒存的話，Codex 讀到的還是舊的。

  3. Markdown：幾個符號就有格式。# 大標題、## 小標題、- 清單、- [ ] 打勾框、- [x] 打勾了、`檔名` 程式字、| 表格。在分頁列右上按 Open Preview to the Side（⌘K V；Windows：Ctrl+K V），右邊就看得到排好的樣子。

  4. 這門課的 .md。AGENTS.md（Week 3）、VERIFY.md（Week 5）、PLANS.md（Week 7）都是 Markdown：規則、驗收清單、計畫都寫成 .md。你寫的 AI 看得懂，AI 寫的你也看得懂。

補充 2AI 為什麼會說錯：模型、token、用量

  1. 它一段一段接下去寫。AI 的模型每一步都挑「最可能接在後面」的那一段（簡化版的說法）。它在乎的是通不通順，不是查過對不對。

  2. token：它讀、寫的單位。一個 token 可能是一個字、一個英文單字，或半個單字（每個模型的切法不一樣）。你打的字、它讀的檔案、它寫的回答，都是一個一個 token。

  3. 知識有截止日，也會很有把握地說錯。模型的知識停在訓練的那一天，之後才發生的事它不一定知道（例如 2026 年 7 月起，Codex 在 ChatGPT 桌面 app 裡）。不知道的時候，它也可能照樣很有把握地回答。請它找論文，它可能列出一篇看起來很像真的、其實查不到的。

  4. 怎麼辦。請它附上來源，自己點開看；重要的事，照你的清單驗收。聽起來對，不等於真的對。

  5. 用量，也是 token 算的。你打的、它讀的、它寫的都算 token：讀得越多、寫得越多，用得越快。

  6. 兩種上限：每 5 小時、每 1 週。每 5 小時：從你開始用的那一刻往後算 5 小時，這段時間內用完了，就要等時間到才能再用（例如 09:00 開始、10:30 用完，要等到 14:00 才又是滿的）；趕作業時最容易碰到：一口氣用太多，就得停下來等。每 1 週：一週加起來的總量，這週用完了，就算 5 小時恢復了也要等到下週。兩個上限同時在算，碰到哪一個都要等。Free Plan 則通常是一個月一定的額度。還剩多少、什麼時候恢復，在 Codex 的設定（Usage）看得到；作業別拖到最後一天。

補充 3說不清楚，就給它看：截圖、檔案、路徑

  1. 用說的，很難說清楚。小安的網頁有個地方怪怪的，跟 Codex 說「網頁上面那裡怪怪的，幫我修」，它看不到你的畫面，只能反問：標題、頭像，還是興趣那一排？

  2. 截圖，貼給它看。把那一塊畫面截下來（直接複製：Mac ⌘ Control ⇧ 4；Windows Win ⇧ S），回到 Codex 按 ⌘V（Windows：Ctrl+V）貼上，再說一句「這裡的興趣標籤擠出去了，幫我排整齊」。它看到你看到的，一張圖比一長串描述清楚。很多人不知道可以截圖問，知道和不知道，差很多。

  3. 檔案：直接拖進輸入框。要它讀某個檔案，從 VS Code 左邊的檔案清單把它拖進 Codex 的輸入框，它就知道是哪一個檔案。圖片檔也能這樣拖進去。

  4. 複製路徑：Codex 和 VS Code 一起開。老師的習慣是 Codex 和 VS Code 同時開著：左邊 VS Code 看檔案，右邊 Codex 交代事情。在 VS Code 左邊的檔案按右鍵，選 Copy Relative Path（從專案資料夾算起的路徑，例如 資料/介紹.md），貼給 Codex，不用自己打、也不會打錯。兩個檔案都叫 介紹.md 時，看路徑就分得出來。
